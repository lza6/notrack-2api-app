### 2.2 请求链路（双通道）

```
OpenAI/Anthropic 客户端
  → wb_proxy.py :8788（ThreadingHTTPServer，bind 127.0.0.1）
    → 鉴权（settings.json api_keys；面板会话豁免仅限管理路径）
    → FC 注入（duck_fc：tools → 协议文本）
    → 通道选择（wb_proxy.py:22539）
       ├─ DUCK_PURE=1 默认 → duck_pure.py
       │    curl_cffi(chrome) → GET /duckchat/v1/status 拿挑战
       │    → Node vm 沙箱（duck_challenge_shim.mjs）→ 官方后处理（duck_vqd_answer.mjs）
       │    → POST /duckchat/v1/chat（durableStream，RSA JWK）
       └─ DUCK_PURE=0 兜底 → duck_client.py
            CDP Chrome 出口池（每出口独立用户目录+可选代理）
    → SSE 帧转写（duck_upstream：action:success → chat.completion.chunk）
    → FC 回解析（<tool_call> → tool_calls, finish_reason=tool_calls）
    → 用量记录（usage/*.jsonl）→ 面板 /dashboard.html
```

## 4. 最强自我反驳与盲点扫描

**反驳 1："backend 双拷贝有人工流程兜底，没问题"**
→ 已被事实击破：本轮 `diff -rq` 捕获 pyc drift，且 `duck_pure.py`（最新核心模块）**只在 gateway 一侧存在**。若今天打 exe，extraResources 打进去的 backend 里没有 duck_pure——桌面版纯协议通道直接缺失，启动即 fallback CDP 或报错。反驳不成立，单源化是 P1。

**反驳 2："零测试可接受，手工点过了"**
→ wb_proxy.py:22537 的通道选择、duck_fc 的 `<tool_call>` 流式缓冲（一旦出现前缀即缓冲不外发）、多轮 messages 拼接（2b253cb 的 400 绕过）全是易碎纯函数。duck.ai 改挑战版本时，回归只能靠手点+起服务，一次 10 分钟起。测试不是形式，是风控对抗迭代速度的杠杆。反驳不成立。

**反驳 3："23442 行 wb_proxy 是历史包袱，必须先拆再谈别的"**
→ 反驳该反驳：拆分 23k 行在高风险期（挑战版本刚换、双拷贝未收敛）引入的回归风险 > 收益。先 v1.1 收敛单源 + v1.2 测试基线，让拆分有安全网后再动（v1.4）。顺序本身是决策。

**盲点 1（供应链）**：mihomo 内核"首次自动下载 ~30MB"（README），无哈希校验——节点转发的是用户全部对话明文，下载源被投毒 = 中间人。免费代理源同理：**用户对话经不可信第三方 IP 出境**。README 有"自用/风控自负"声明，但 exe 分发后风险转嫁给不知情使用者。

**盲点 2（import 兼容层）**：wb_accounts.py:19-27 有一段 `_DuckShim`/`removed-module shims`——"只做减法"留下的签名兼容壳。新会话读代码会被误导以为这些模块存在。需在 v1.1 盘点并注释清零。

**盲点 3（x-fe-version 硬编码）**：`serp_20261027_103404_ET-...` 写死在 duck_pure.py:25。duck 前端任意发版 → 418/挑战失败。**当前没有版本漂移的探测与告警**，失效后用户只会看到"chat 无响应"。建议 v1.3 做自动探测（status 请求失败模式识别 + 面板红条）。

**盲点 4（打包机依赖）**：main.js 期望 `backend/python/pythonw.exe` 或打包机 PATH——F9 实证 `backend/python/` 不存在。换一台机器打包，exe 可能 spawn `pythonw.exe` 失败且只有日志无 UI 提示。需打包自检脚本。

**盲点 5（绑定面）**：默认 bind 127.0.0.1（好），但 wb_proxy.py:20389 注释提到 0.0.0.0 bind 的可达性处理——若面板提供 bind 配置且用户改 0.0.0.0，免密直进逻辑（本机回环判断）是否仍正确豁免？**待验证**，公网暴露 + 免密 = 面板裸奔。

**盲点 6（README 漂移半径）**：README 是其他 AI/新会话的第一输入源。目录节已过时（F11）；`.gitignore` 顶层还有 `backend/`、`accounts/` 等整目录忽略规则靠特例豁免（441e59e 提交注明确有误伤史）——规则与现实的映射脆弱。

## 6. 方案对比与权衡矩阵

### 方案 A：维持双拷贝 + 同步脚本（传统）
打包前 PowerShell 脚本把 `gateway/` 全量拷到 `backend/gateway/`，挂进 `npm run dist` 前置钩子。
- 说明：1 小时完成，不动任何运行路径；drift 交给脚本纪律。
- 评估：治标；人忘一次即 drift；两份代码永久存在；对 P1-4 无帮助。

### 方案 B：backend 单源化（优化）★推荐
`backend/` 不再拷贝 Python 源码。改 `desktop/main.js`：`BACKEND_DIR` 指向仓库根、`SCRIPT = wb_proxy.py`（根薄壳自带 sys.path 注入 gateway）；electron-builder `extraResources` 改打 `../gateway` + `../wb_proxy.py`。`backend/` 仅留非源码文件；P1-4 顺带解决（打包自检 + 依赖本机 python 的假设写明）。
- 评估：物理单份权威，drift 根除；打包天然最新；符合"只做减法"；改动面小（main.js ~3 行 + package.json extraResources + 删 backend 源码拷贝）。
- 风险：打包后资源路径需真机验证一次；可 git revert 回滚。

### 方案 C：拆分 wb_proxy.py + 全面工程化（创新，远期）
按职责拆 panel/auth/usage/channel/proxy 模块，补 pytest + GitHub Actions（lint+test+打包冒烟）。
- 评估：根治可维护性；但 23k 行拆分回归风险高、周期数天，与"不大重构"拍板冲突；**必须排在测试基线之后**。

### 方案 D：挑战版本漂移自愈（风控专项，可并入 v1.3）
status 请求失败时自动抓取 duck.ai 首页 HTML 提取最新 `serp_*` x-fe-version，热更新内存值 + 面板显示当前版本与最后成功时间。
- 评估：直击 P2-5，把"静默失效"变"自愈+可见"；实现量小（~50 行），独立于重构路线。

### 权衡矩阵

| 维度 | A | B★ | C | D |
|---|---|---|---|---|
| 技术可行性 | 高 | 高 | 中 | 高 |
| 开发成本 | 极低 | 低 | 高 | 低 |
| drift 根治 | ✗ | ✓ | ✓ | n/a |
| 与"不大重构"约束 | 合 | 合 | **冲突** | 合 |
| 回归风险 | 极低 | 低 | 高 | 低 |
| 对 P1-4 帮助 | 无 | 顺带解决 | 无 | 无 |
| UI 可见性提升 | 无 | 无 | 无 | **✓** |

**决策建议**：v1.1 = B（+A 思想的打包前置同步作为 B 未达时的兜底）；v1.2 = C 的"测试先行半步"（只加测试不拆码）；v1.3 = D + EBUSY；v1.4 = C 主体（需用户解除约束）。

## 11. 质量门禁与证据要求

1. 任何"已完成/已修复/已闭环"必须附：命令 + 真实输出摘要（状态码、diff、时间戳、截图之一）。

3. 回归门禁：改动鉴权、通道选择、SSE 转写代码后，必须重跑任务 1 三条 curl + 一发 stream chat。
4. 涉及删除（如 backend 拷贝）前：确认 desktop/main.js 已无源码引用（grep 证据）+ 真机验证已过。
5. 验证标签纪律：已验证（实际运行）/ 静态确认（读代码）/ 合理推断 / 待验证——四标不得混用。
6. 文档模式禁令：待执行项一律标"待执行"，附命令/预期/证据/回滚四要素。
