# 技能：计划文档闭环审计（plan-doc-audit）

## 适用场景
审计 docs/ 计划、改进指南、路线图类文档是否"写在纸上"与"落在地上"一致。

## 前置读取
- .agent/memory/project_specs.md（权威事实基线）
- git log（近期实施提交）

## 步骤
1. 扫描全部 md（排除 README 门面/归档/依赖目录）。
2. 逐条提取任务 → 台账（ID/描述/验收标准/当前状态）。
3. 判定口径：真实实现 + 真实链路 + 真实验证（运行过的命令）+ 证据 = 已闭环；缺一即未闭环。
4. 文档自称"已完成"的：抽查证据可复现性，证据缺失→重新验证。
5. 输出：已闭环/部分/伪/未闭环/需决策/过时/不适用 分类表。
6. 归档（用户批准后）：复制到 docs/archive/plans/YYYYMMDD/ + archive-manifest.md（含判定摘要与回滚方式）→ 删原文件。
7. 未闭环项提炼至 .agent/memory/known-issues.md（永不随文档一起消失）。

## 验收标准
每条任务有状态 + 证据链接；归档有 manifest；known-issues 吸收全部未闭环项。

## 常见坑
- "文档说已完成"≠闭环（本次指南多项自称完成的实际证据在 git 历史里，需考古）。
- 归档≠删除记忆：未闭环任务必须先搬家再删文档。
